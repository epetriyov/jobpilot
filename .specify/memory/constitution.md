# JobPilot Constitution

> Высший приоритет в проекте. Размещается в `memory/constitution.md` при `specify init`. Все спеки, планы и задачи spec-kit проверяются на соответствие этим принципам; при конфликте побеждает constitution. Изменение constitution — только явным решением пользователя.

## Принцип I. Домен чист, слои нерушимы
Бизнес-правила живут только в `app/domain/` — без I/O, без фреймворков, единый язык из docs/DOMAIN.md дословно. Направление зависимостей: domain ← ports ← application ← (adapters | bot | worker | mcp). Контролируется import-linter в CI; нарушение — блокер мержа.

## Принцип II. Test-first, без исключений
Ни одна строка прикладного кода раньше падающего теста (red → green → refactor). Кейсы — docs/TEST_CASES.md; новая функциональность добавляет кейсы в том же PR. Пирамида: unit (чистый домен) → contract (golden-файлы, фейковые провайдеры) → integration (testcontainers) → eval. Красные тесты в main запрещены.

## Принцип III. LLM — измеряемая зависимость
Каждая LLM-задача имеет: версионируемый промпт, pydantic-схему выхода (через instructor), append-only eval-датасет с порогом и запись llm_call + Langfuse trace. Изменение промпта или модели без eval-прогона и сравнения отчётов — незавершённая работа. Провайдер и модели — только из конфига; хардкод имени модели — блокер. Внешние тексты (вакансии, письма) — недоверенные данные: экранируются в промптах, не могут инициировать действия.

## Принцип IV. Безопасность по умолчанию
Секреты — только env (600 на VPS, sops/age в репо); в код, логи, промпты и MCP не попадают никогда. Тела писем не логируются. Действия, нарушающие ToS внешних сервисов (автоматизация LinkedIn, обход капчи), не выполняются — эскалация пользователю. Внешние записи (publish, боевой дайджест) уважают DRY_RUN. MCP: auth-токен, localhost/туннель, read-роль БД, белый список write-инструментов.

## Принцип V. Наблюдаемость — не опция
Каждый job → JobRun + OTel root span; каждый шаг use case → child span; каждая ошибка — structlog с контекстом и trace_id. Каждый LLM-вызов учтён в затратах (llm_call.cost_usd по прайсу из конфига). Новый источник или задача без метрик и логов не считается готовой.

## Принцип VI. Человек в контуре
Агент готовит — пользователь решает: отправка писем и инвайтов только вручную; новые источники проходят DRY_RUN и canary до явного одобрения; качество подбора измеряется agreement rate через /review. Автоматизация никогда не совершает необратимых внешних действий без явной команды пользователя.

## Governance
Каждый этап PLAN.md = feature в spec-kit: /speckit.specify → /speckit.plan → /speckit.tasks → TDD-реализация. PR проходит CI (lint, типизация, слои, тесты, recorded-eval) и агент-ревью на соответствие спеке и constitution. Этап закрыт только после ручной проверки пользователем. Уточнение домена → обновление DOMAIN.md и TEST_CASES.md в том же PR.
