# TEST_CASES.md — тест-кейсы JobPilot (TDD)

> Контракт качества. Каждый кейс реализуется как тест ДО прикладного кода (red → green → refactor).
> Формат: `[ID] Given / When / Then`. Уровни: **U** — unit (чистый домен, без I/O), **C** — contract (адаптеры, golden-файлы, моки HTTP), **I** — integration (БД/compose), **E** — eval-датасет (LLM-качество, метрика + порог).
> Новая функциональность = новые кейсы в этом файле в том же PR.

---

## 2. RELEVANCE (этап 1, развитие на этапе 6)

Домен (U):
- [R-U1] Given ответ LLM `{"score":150,...}` или не-JSON → Then ровно 1 retry; повторно невалидно → вакансия skip, warning, пайплайн жив (R2).

- [R-U5] Given вакансия уже скорена текущей prompt_version → Then повторный вызов LLM не происходит (R1).

Контракт (C):
- [R-C1] Given фейковый LlmPort → Then промпт содержит профиль резюме, few-shot, текст вакансии и НЕ содержит ни одной строки из env (регэксп-проверка на значения секретов из тестового окружения).
- [R-C2] Единый contract-suite `LlmPort` параметризован по всем адаптерам (instructor_openrouter на записанных ответах, fake; прямые адаптеры провайдеров — по мере добавления): одинаковые входы → валидная pydantic-схема на выходе, валидационный retry ровно 1 (max_retries instructor), после — graceful skip; запись `llm_call` создаётся у каждого адаптера, cost_usd берётся из usage ответа (фолбэк — прайс конфига). Свап модели не должен ломать ни один тест suite.
- [R-C3] Given конфиг `LLM_MODEL_SCORING=<другая модель>` → Then скоринг идёт через неё без изменения кода (проверка по записанному имени модели в llm_call).

Eval (E):
- [R-E1] Датасет `relevance` (≥30 размеченных на этапе 1, пополняется постоянно): precision ≥0.7 / recall ≥0.7 на baseline; каждая новая версия промпта — сравнение с прошлым отчётом, регресс F1 >0.05 = блокер.

## Приложение: формат eval-датасетов

`eval/datasets/<name>/vN.jsonl`, одна строка = один пример:
```json
{"id": "...", "input": {...}, "expected": {...}, "meta": {"added_at": "...", "source": "manual|review|dryrun"}}
```
Датасеты только растут (append-only), версия фиксируется в отчёте. Раннер: `make eval CONTEXT=<name>` → метрики в stdout + `eval/reports/<name>_<date>.md` + Langfuse dataset run. Пороги из этого файла зашиты в раннеры как assertions.
