# ADR-001: Волна D (Navio/МТС/RWB) построена вперёд спеки — ретроспективная синхронизация

- **Дата**: 2026-08-14
- **Статус**: Принято
- **Контекст**: specs/005-sites (Этап 5, скрейперы карьерных порталов)

## Контекст

Код этапа 5 уехал вперёд спеки: в `app/config.py` (`KNOWN_SITES`), `registry.py`
(`SITE_ADAPTERS`) и миграцию `0011_wave_b_sites` добавлены три новых сайта — Navio, МТС,
RWB/Wildberries (публичные JSON-фиды single-employer порталов), с golden- и unit-тестами. Спека
(`spec.md`, `data-model.md`, `env.md`, `plan.md`, `tasks.md`) знала только 7 сайтов. Дополнительно
robots-парсер был заменён с `urllib.robotparser` на `protego` (urllib ложно нормализует
`Disallow: /?` → `/`). Реализация опередила SDD-контур — нарушение порядка «спека → план → код».

## Решение

Синхронизировать спеку с кодом ретроспективно (этот проход): поднять счёт сайтов 7→10, завести
**Волну D** как отдельное имя (не переиспользуя занятые B=Сбер/Т-Банк/Альфа и C=Ozon/browser),
задокументировать выбор `protego`, отметить `mws` как рассмотренный-и-исключённый (🔴 Qrator с
прод-egress). Код и комментарии не трогаем (правка комментариев `registry.py`, где D ошибочно
подписана «волна B», — отдельная задача вне scope).

## Последствия

- Спека и код снова консистентны; исполнитель может работать без доп. вопросов.
- Впредь новый источник идёт по SDD (CLAUDE.md §2): термин → спека/tasks → красный тест → код.
  Опережение кодом спеки — красный флаг ревью контрактов/схем (владелец — system-architect).
